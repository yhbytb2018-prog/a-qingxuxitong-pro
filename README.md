# A股情绪系统 · PRO（云端版）

一个比参考系统更稳的 A 股市场情绪看板：**多源数据 → 七因子情绪 → 题材去噪 → 缺失代理 → 多源容灾**，跑在 GitHub Pages + Actions（零服务器、零费用、自动每日更新）。

## 它比参考系统好在哪（四个已知坑全修）

| 问题 | 参考系统 | 本系统 |
|---|---|---|
| 题材噪声 | 单只票专属诱因被当热门题材，新晋106/退潮155 | 标准词典归一 + 个股去重 + 全局孤点剔除 → 新晋24 / 退潮18 |
| 缺失数据 | 静默填 50，不告诉你 | 用代理指标推算；推不出则中性50并**显式标记** `imputedRatio` + 页面告警 |
| 单点故障 | 数据源挂就断更 | 多源容灾：主源失败自动回退已存档数据并记录原因；新鲜度按交易日历判定（不再粘滞误报）；非交易日自动跳过 |
| 可维护性 | 公式/权重藏在页面里 | 权重/阈值集中在 `src/config.js`，七因子模型透明可审计，带单元测试 |

## 部署（3 步）

1. 把本仓库推到你 GitHub（或 fork 后改名 `a-sentiment-pro`）。
2. 仓库 **Settings → Pages → Build and deployment → Source: GitHub Actions**（2026-10-06 部署治理切换：由 branch 直托管切到 Actions 单通道）。**切换是一次性手工一击**——切换前原生分支构建照常触发（任何 push 都构建、慢、且与 Actions 通道互打）；切换后原生停摆，部署只走 `deploy-pages.yml`。
3. **Actions** 默认开启，交易日多轮自动跑（北京 18:30 首抓 / 21:00 补抓 / 次日 04:30 美股收盘档；盘中每 30 分钟轻量快照不碰档案），`daily.yml` 更新 `data/*.json` 并提交回 main——数据提交命中 `deploy-pages.yml` 的 paths（`data/**`）自动触发页面刷新。
   - **部署单通道**（`deploy-pages.yml`）：paths 正向白名单 = web 面（`index.html`/`app.js`/`style.css`/`sw.js` + SW 外壳资产 + `data/**`）——纯文档变更（`**.md`、`docs/`、scripts/test 等）**不触发任何部署**。
   - **并发防覆盖**：`concurrency group "pages" + cancel-in-progress`——连续 push 只保留最后一次部署，进行中的旧部署就地取消（旧形态两通道互相覆盖的实录与决策见该文件头注）。
   - 首次会看到 `data/archive.json`（已随仓库附带演示种子数据），之后由 live 模式覆盖为真实数据。
   - 想立刻看到效果：Actions 页点 `deploy-pages` → `Run workflow` 手动触发一次。
   - 注：页面 = 根 `index.html` + `app.js`，运行时 `fetch('./data/*.json')` 取数；`daily.yml` 构建的 `dist/`（合并版 UI 单文件）不再部署（通道收口决策见 `daily.yml` 内注释与 `deploy-pages.yml` 头注）。

## 全局配置（config.json · 唯一事实源）

权重/阈值/风控/端点/假日等全局配置自 2026-10-02 起抽离到根目录 **`config.json`**（`schemaVersion: 1`）：

- **Node 侧**照旧 `import config from './src/config.js'`——薄壳加载层会读 JSON 并做启动校验（权重和≠1、阈值乱序、假日格式错 → 直接 throw，不带病运行）；
- **前端**由 index.html 内联 module 脚本动态 `import('./config.json')` 挂到 `window.ASENT_CONFIG`（旧浏览器 import attributes 不可用时静默降级走兜底值；2026-10-03 前此职责由 `paper_ui.js` 承担，台面下线后移交）；
- `app.js`（经典脚本）的 `TH_DEFAULT` 等手抄副本仅作最后兜底保留，**与 config.json 的一致性由 `test/config.test.mjs` 的防漂移断言守护**——改了 JSON 忘改兜底会测试红；
- 审计脚本（`audit_lhb_caliber.mjs` / `check_frontend.mjs`）直接 `JSON.parse` 读值，不再对源码做正则提取。

改配置只改 `config.json` 一处。待收编的存量同值硬编码（下一阶段）：`src/picks.js` 的 `TIER_THRESHOLDS`、`src/paper.js` 的费率/风控常量、`src/health.js` 的 `imputedWarn`、`src/util.js` 的重试默认值。

## 策略回测（V5.2）

页面新增四块：**策略回测 / 网格寻优·帕累托 / 滚动样本外 / 主线自动选股**，数据由 `node scripts/backtest.mjs`
在服务端预计算进 `data/backtest.json`，前端只渲染、零构建。

- **信号**：七因子加权情绪分（权重取 `src/config.js`，与页面 `emotion.value` 及研判报告同口径）；
  四档阈值 80/65/24，收盘打分、**T+1 生效**，过热区只减仓不新建。注意 `hi=44` 是**保留参数**：
  `positions()` 并未用它判档（实际 24~65 同属半仓），仅用于历史口径展示，详见 `src/config.js` 注释
- **标的**：三大指数（上证/深证/创业板）各自独立按同规则回测 → 日收益等权合成组合（多标的轮动）
- **V5.2 增强口径**：交易成本（佣金万3双边/印花税万5卖出/滑点万2，按仓位变动幅度计提）、
  单日仓位变动上限（平滑，止损不受其约束）、单笔止损、回撤动态降仓、最大仓位约束
- **网格寻优**：七因子权重以基准为锚做倍数扰动后归一化（默认 5 档 → 78,125 组），
  双目标帕累托（夏普↑ × 最大回撤↓）；不同权重常落在同一阈值档位平台、目标值重复，故结果表按目标去重并标 `非支配`
- **滚动样本外**：固定权重切段评估 vs 逐窗重寻优（walk-forward，每段用训练窗重选权重再评测试窗）
- **主线自动选股**：按当日题材榜涨停家数取主线题材 → 热点榜中诱因含该题材的强势股为标的清单，
  强度分 = 主线涨停家数 × 题材密集度（与离线 Python 版 `find_main_line` 同形，数据源不同故量级不可直接比较）

引擎语义与离线 Python 工具 `tools/backtest/sentiment_backtest.py` 严格对齐，并由 `test/backtest.test.mjs`
的跨语言一致性用例逐位比对（夹具 `test/fixtures/parity_v52.json` 由 Python 侧生成）；
改任一端语义后需重跑 `tools/backtest/make_parity_fixture.py` 并提交新夹具。

> 诚实说明：回测样本仅随存档累积（当前 32 个交易日），年化/夏普等指标的统计意义有限，
> 仅用于管线自检与参数对比，**不构成投资建议**。样本短时两目标可能同向、前沿退化为单点，页面会显式标注。

## 策略收益回测（③ · 三个具体策略 · 2026-10-02）

`node scripts/backtest_strategies.mjs` → `data/backtest-strategies.json`（核心模型在 `src/strategy_bt.js`，
与单测共享——`test/backtest_strategies.test.mjs` 用「作弊探针」锁死 point-in-time 时点纪律）。

| 策略 | 入场 | 出场 |
|---|---|---|
| A 冰点反转 | T日 情绪 < 10 → T+1 开盘买沪深300 | 持有 N 日（3/5/10）收盘卖；期间情绪 > 90 → 次日开盘清仓 |
| B 题材动量 | T日 top1 题材（去噪口径）→ T+1 开盘等权买成员股 | 持有 N 日收盘卖 |
| C 梯队风险偏好 | T日 max_lb≥4 且 2板+家数≥8 → T+1 开盘买沪深300 | 持有 N 日收盘卖；期间 max_lb≤2（断层）→ 次日开盘清仓 |

- **point-in-time 铁律**：信号只读 T 日收盘字段；成交一律 T+1 开盘价；重叠信号不加仓；
  成本与 V5.2 同口径（双边佣金+印花+滑点 ≈0.13%/往返）。
- **基准**：沪深300 买入持有（同区间）。
- **如实披露**：当前样本仅 33 个真实交易日（208 个 s_net 单因子回填天全部排除），
  样本期情绪区间 29.9~85.6——**策略 A 触发 0 次**（无冰点/过热日）是事实不是 bug；
  B/C 的负收益在基准同期 -6.6% 的下跌段里，样本量不具统计意义。
- ⚠ **免责**：历史回测 ≠ 未来收益。结果仅用于管线自检与口径演示，不构成投资建议。

## 研判报告（口径与回测引擎同源）

（正文见页面「研判报告」分区；此处记录报告的三种"带走"方式——内容与屏幕所见**严格同一份**。）

**复制 / 导出 / 打印**：报告工具条右侧三个动作，全部消费**屏幕上已渲染出来的那份 DOM**
（`parseReport` 只做格式转换、不重算任何指标——若导出另写一套拼接，数字迟早与屏幕漂移）：

- **复制全文**：纯文本（无 HTML 标签、无 Markdown 记号），可直接粘贴到微信/邮件/记事本；
  涨跌值转成 ↑/↓ 箭头。Clipboard API 不可用时自动回退 `execCommand`。
- **导出文档**（▾ 三种格式）：
  - **正式文档（HTML）**——推荐。自包含单文件（内联样式、无脚本、无外链），正式报告排版：
    页眉（机构/标题/数据日期/导出时间）→ 数据落款条 → 编号章节（①~⑥）→ 口径附注 → 免责声明。
    A4 打印就绪（`@page` 边距、章节防断页），**下载后直接 Ctrl+P 即可打印，无需任何修改**。
    白底黑字（刻意不跟随站点深色主题——导出文档是要发给别人、拿去打印的）。
  - **Markdown**——粘进知识库/文档系统，标题层级与屏幕一致（`#` 报告 / `##` 章节 / `###` 段内小节）。
  - **纯文本**——记事本/邮件正文。
- **打印**：把正式文档 HTML 写入隐藏 iframe 后调 `print()`——打印出来的版式与导出文档完全一致，
  而不是把整个深色看板打出来。另外给整页写了 `@media print` 兜底：直接按 Ctrl+P 也会
  自动只保留报告区、强制展开折叠段落、转白底黑字。

**两处只有踩过才知道的坑（都已有守卫锁死）**：

- **导出/打印稿的折叠件标签与屏幕**刻意**不同**：屏幕写「🔍 点击展开查看口径」（那是真能点的），
  导出（HTML/MD）与打印稿写「📎 口径说明（附）」——静态文档/纸面上"点击"是一句**做不到的邀请**，
  读者找不到可点的东西只会以为文档坏了。两个常量（`CALIBER_SUMMARY` / `CALIBER_SUMMARY_DOC`）
  都在 `src/report.js`，由 `audit_lhb_caliber.mjs` 的模板契约块**反向锁死"必须不同且导出不含『点击』"**，
  防止哪天被人图省事重新合并成一份文案。
- **打印时折叠件必须用全量选择器展开**：`.bf-caliber` 的**子内容跨多种标签**（段落/列表/表格）。
  只写 `> p, > ul { display:block }` 会漏掉表格等情形——而且**旧断言恰好也写死了这两种选择器**，
  于是"只展开两种"这个 bug 能一路通过守卫（守卫自己锁住了 bug）。现改为
  `details.caliber > *:not(summary) { display: block !important }` 全量兜底，
  断言同步改为校验全量选择器。
- **`<details>` 未 `open` 时子内容在 Chromium 里不生成盒子**：所以"给后代写 display"是无效的，
  必须靠上面的全量规则让折叠件在打印语境下表现为常开容器（同时去掉 summary 的三角标记）。

**单独刷新（↻ 刷新报告）**：报告工具条首位的按钮。与顶栏「↻ 刷新」的区别：顶栏刷新
重算整页（行情/题材/回测全部重渲染），而它**只重建研判报告**——重新拉 archive、
重跑报告链路，并连带重取报告依赖的回测档（落款版本/档位阈值取自 `data/backtest.json`）。
两处设计防「刷新即失忆」：① 重渲染前记录已折叠段落，**等所有重渲染结束**（含
`loadBacktest` 内部的第二次 `renderBrief`）之后再还原折叠态——真浏览器核对抓到过
「先还原、后被覆盖」的时序 bug；② 不调 `window.scrollTo` 还原滚动（只换 `#briefBody`
的 innerHTML，文档高度基本不变，浏览器自然保持视口；且 scrollTo 在 jsdom 会触发
「Not implemented」jsdomError）。状态文字如实告知：数据有变→「已更新」、无变→
「已是最新」、失败→「刷新失败：原因」，用 `aria-live=polite` 播报。

导出引擎 `src/report.js` 与解析单测 `test/report.test.mjs`：纯文本无标签残留、HTML 自包含
（无脚本/无外链/标签成对闭合/防注入转义）、Markdown 层级、文件名按数据日期命名、白底配色等
都是**锁死的契约断言**；`check_frontend.mjs` 再用真实渲染的报告核一遍导出全链路。


`index.html` 的「研判报告」是**纯前端规则引擎**，由当档 `archive.json` 推导，无手写文案。V5.2 起
它的结论口径与回测引擎打通——此前是两套独立口径，实测**同一交易日会给出相反结论**（报告自算的
五模块分 83.8 →「极低风险/过热」，引擎的七因子分 76.8 →「满仓持有」）：

- **主结论 = 引擎口径**：用七因子加权情绪分（= 页面 `emotion.value`）套 `data/backtest.json` 的
  `params.thresholds`，输出可执行的**仓位档位**（≥80 过热只减仓不新建 / ≥65 满仓 / 24~65 半仓 / ≤24 清仓）。
  阈值从 `backtest.json` 读，是单一真相源，前端不硬编码（回测档缺失时回退到与引擎同值的默认表）。
- **五模块分降级为「因子分解」**：V5.0 的情绪/盈亏/广度/题材/主线结构（25/25/20/20/10）复合分仍展示，
  但只解释结构构成，**显式标注不参与档位判定**；与之配套的「极低风险/极高风险」五档措辞已移除
  （它既与引擎语义相悖，边界 45/25 也与引擎 44/24 不一致）。
- **资金面与打分的关系（易被写错，单列）**：V5.0 五模块**不含**资金面，但 V5.2 主分数是**七因子**情绪分，
  其中 **龙虎净额 `s_net` 占 20% 权重**（`src/config.js` `weights.s_net20`）。因此正确表述是
  「资金面不在五模块分解里、但**参与**主分数与档位」，**绝不能**写成「资金面不参与打分」——
  报告 §② 标题、口径备注、`auxWarn` 措辞曾因沿用 V5.0 旧文案而与本条冲突（同一句里既写「龙虎净额20%」
  又写「资金面不参与打分」），已修正并由 `scripts/audit_lhb_caliber.mjs` 加守卫锁死。
- **落款**：报告顶部标注数据日期、抓取状态（与 `src/freshness.js` 三态一致）与打分模型版本。
- **主线口径对齐**：§5 题材结构补「主线强度分 = 涨停家数 × 密集度」，与引擎 `selectMainLine` 同式。
- **V5.2 实盘约束**：报告附止损 -8%、回撤 ≥15% 动态降仓、单日仓位变动 ≤20%、佣金/印花税/滑点口径。

守护方式：`scripts/check_frontend.mjs` 的断言（含「报告档位 == 引擎阈值推导的档位」
「不得出现『极低/极高风险』措辞」），加上 `test/backtest.test.mjs` 直测 `positions()` 的实际仓位
与档位语义一致——任何一端漂移都会让测试变红。

## 外围市场观测（隔夜 / 节后预案）

页面「区五 · 外围市场」把**隔夜外围**做成可核验的数据底座，数据由 `node scripts/fetch_global.mjs`
预计算进 `data/global.json`。它解决的是一个具体问题：长假 A 股休市，人只能手抄新闻里的美股数字
去推断节后开盘，抄错一个数没人能发现。

- **品种（16 个，全部来自新浪行情，逐位核对过字段布局）**
  - **A 股锚**：`富时中国A50期货`（新加坡交易所，**A 股休市期间照常交易**，是长假里唯一实时定价 A 股权重的品种）
  - 美股宽基：道指 / 标普500 / 纳斯达克 / 纳斯达克100；行业：**费城半导体（SOX）**；
    中国资产：纳斯达克中国金龙指数、富时中国 ETF（FXI）
  - 中国香港：恒生指数 / 恒生科技；汇率：美元指数 / 离岸人民币 / 在岸人民币
  - 商品：COMEX 黄金 / WTI / 布伦特
- **为什么盯这些而不是道指**：A 股常见的是「大盘分化、成长杀跌」的结构（2026-09-30 上证 +0.31%，
  但科创50 -2.51%、半导体与元件领跌）。道指金融/消费权重高，在这种结构里用道指推 A 股方向经常是反的；
  同源度最高的是 **A50 期货（权重定价）+ 费半（电子链同一批终端需求）+ 纳指（成长风格）+ 金龙（外资对中国资产）**。
- **映射写成数据**：`src/global.js` 的 `GLOBAL_ANCHORS` 声明「品种 → A 股板块 + 同向/反向 + 为什么」，
  前端不重写一份；点条目可看口径。
- **触发式观测**：阈值定义在 `WATCH_THRESHOLDS`（构建期随 JSON 下发）。**主锚必报**（A50/费半/金龙，
  未触发也给读数）、**次锚触发才报**（纳指/汇率/商品/港股）。加权净倾向 `bias`，`|bias| ≥ 2` 才给方向。
- **三处口径纪律**（与 `src/lhb.js` 同源，都由真实故障教出来）
  1. **涨跌幅一律用 `last/prevClose` 现算**，同时保留数据源原值 `chgPctReported`——两者不一致即口径漂移。
  2. **取不到就是 `null`，绝不 `|| 0`**。尤其注意 `0` 是合法行情值：费半 2026-09-30 收平于 **-0.0043%**，
     写成 0 或带上负号都会把「收平」读成「没波动/下跌」，故 `fmtPct` 专门抹掉 `-0.00%`。
  3. **合约月份要写明**。2026-09-30 媒体普遍引用布伦特 **103.53**，那是**当日到期**的 11 月合约结算价；
     同源数据报的 **98.03** 是更活跃的 12 月合约。两个都对，混用会得出错误结论（详见代码注释）。
- **与 A 股存档分开成两个文件**：外围在 A 股休市期间照常更新，合成一个文件会让「A股没更新」与
  「外围没更新」互相掩盖；外围加载失败只影响本区。
- **诚实缺口**：新浪不提供美债收益率（`gb_$tnx` 返回空），故**长端利率这一分母端锚点暂缺**，
  目前只能通过美元指数/黄金间接观察；VIX 同样不可得。

守护方式：`test/global.test.mjs`（24 例，含真实响应夹具逐位断言）+ `scripts/check_frontend.mjs`
（行情表与卡片同源同序、费半收平不渲染成 -0.00%、映射条数与快照一致等 11 条）。

## 研判推荐（src/picks.js + src/predict.js）

一句话：**只推荐「预测买入后大概率会涨」的票，大概率亏的直接剔除**。
`src/picks.js` 管候选池构建与去噪，`src/predict.js`（2026-10-01 新增）管预测与剔除——
它回答的问题是「这只票买入后大概率会涨吗」，而不是「这只票今天有没有资金」。

**预测引擎的实测依据（33 个交易日真实前瞻收益回溯）**：抓取候选池 1274 只票的腾讯前复权
日 K，对每日候选做 T+1 / T+3 前瞻收益统计，用实测数字定规则、不拍脑袋给权重：

| 分组 | 样本 | T+1 均收益 | 上涨占比 | 结论 |
| --- | --- | --- | --- | --- |
| 全部涨停股（基准） | 975 | +1.59% | 55.3% | 基准线 |
| 龙虎榜净买 > 0 | 764 | +0.81% | 50.5% | **弱于基准**（旧口径缺乏预测力的证据） |
| 净买 ≥ 2 亿 | 108 | +1.96% | 64.8% | 有效正向因子 |
| 2 连板 | 130 | +2.73% | 59.2% | 有效正向因子 |
| 2 连板 & 换手 < 10% | 72 | +3.30% | 65.3% | **最强组合**（中位 +4.99%） |
| 涨停 & 换手 ≥ 25% | 78 | +0.65% | 46.2% | **必须剔除**（T+3 −2.65%，3 日平均最大回撤 −8.40%） |

关键结论：**正期望只在「T 日收盘价买入」口径成立；T+1 开盘追高是负期望**（首板 & 低换手组
T+1 均 −0.30%）。所以每只推荐都同时给两种口径的预期，并明写「别开盘追高」。

| 环节 | 做法 | 为什么不偷懒 |
| --- | --- | --- |
| 候选池 | **只收两种票**：当日龙虎榜净买 > 0，或当日涨停（含 `summary.zt_codes` + 连板数）。区间累计榜、新股/无涨跌幅限制个股、净买为负的票一律剔除 | 没有上榜就没有真实资金证据，推荐它等于凭感觉；区间榜的净买是连续 N 日累计值（混入会让区间票无脑霸榜）；新股涨跌幅可达 200%+ 与正常个股不可比 |
| **预测（新增）** | `predictUpProb` = 基准上涨占比 55.3% + 实测边际修正（连板高度/低换手/大额净买/稀缺日/20% 品种，封顶 +18pt）；**6 条硬剔除**：换手≥25%、连板≥5、北交所、ST、无涨停且无净买、仅小额外资金（<2 亿且无涨停） | 概率分 = 历史同特征组的实际上涨占比，是**可核验统计量**而非主观置信度；每只票同步给出命中的因子、各组实测数字与样本量（木桶原理取最小样本），不足 50 例明说「不足以下结论」 |
| 不静默丢弃 | 进池的每只票必落在四个桶之一：推荐 / 已剔除（含逐条实测原因，折叠面板）/ 未达概率门槛 / 被 topN 截断 | 「静默丢弃」会让人以为池子里本来就没有这些票；剔除原因必须带实测数字，可复核 |
| 评分（展示用） | 加权合成 0~100：资金 40% + 连板 25% + 主线题材 20% + 流动性 15%。**仅供观察，不参与预测排序** | 每一维都对应一个可核验的原始字段；预测排序只认实测因子，两套口径不混用 |
| 理由/风险 | 理由逐条对应真实字段（净买 X 亿 / N 连板 / 属主线题材 / 换手 X%）；风险逐条具体（N 连板断板回撤 / 高换手筹码不稳 / 次日冲高回落 / 20% 品种波动大 / **无龙虎榜净买=证据强度弱**） | 只说「注意风险」等于没说；涨停入选而无资金证据的票必须明说证据强度弱，不冒充强票 |
| 仓位与止损 | **与市场档位联动**：情绪分 → V5.2 阈值 → 档位定总仓位，个股均分（单只上限 20%）。止损线取 `alerts.js` 的 `POS_CFG.stopLoss` 同源传入（避免互引）；20% 涨跌幅品种**仓位打 6 折而非放宽止损** | 逆着档位推荐重仓是自相矛盾；宽波动品种该减仓不该松纪律 |
| 交互 | 点个股行 → 详情抽屉五段（预测依据/预期收益两口径/止损与仓位/原始证据/旧展示分）；「填入下单」只填代码不提交——**绝不替用户下单** | 脚注与抽屉均明示「概率是历史统计，不是收益承诺」且「不构成投资建议，买卖由你自行判断」 |

**主线题材匹配的两级诚实口径**：`main_theme.name` 可能是**聚合桶标签**（实测「业绩线」在当日
56 只热点股的诱因文本中出现 0 次，而「业绩增长/业绩预增」出现多次），只做字面匹配会让主线判定
恒为 false（既有 `scoreMainStructure`/`selectMainLine` 也有同样盲区）。这里做两级匹配：
精确命中（诱因含主线名）→「属当日主线题材」；词根命中（诱因含与主线名共享 2 字词根的**当日
题材词**，不从任意文本里猜）→「与主线题材同源（词根匹配）」，评分给 0.6 不冒充满分。

**踩过的坑（都有回归测试）**：① `scoreFund(null)` 曾被 `min:0` 分档当成「净买为正」给 0.35 分——
`NET_STEPS` 最低档改为 `min:1` 并在函数里显式拦掉 ≤0；② `marketTier('')` 因 `+''===0` 被误判成
清仓档——空串显式返回 null；③ 同票既有龙虎榜又涨停时，热点榜的业务诱因被龙虎榜上榜原因覆盖，
题材匹配全部落空——两个字段都保留并取并集匹配（该修复让候选题材命中率从 0 升到 39/71）。

### 连板概率：另一个预测目标（predict-v2 · 2026-10-01 追加）

**「上涨」和「连板」是两个不同的预测目标，绝不能混用。** 实测证据：全部涨停股 T+1 上涨占比
55.3%，但 **T+1 再涨停只有 21.8%**；把上涨概率当连板概率用会严重误导（首板 & 低换手组上涨概率
≥64%，连板概率却只有 18.2%）。所以连板单独立模，且**只对「当日已涨停」的票给概率**——
未涨停的票返回 `prob: null`（语义是「不存在」而不是 0），连板数缺失时同样不给。

实测依据：`scripts/backtest_limit_up_streak.mjs` —— 1089 只票 × 33 交易日前复权日 K 前瞻，
**2118 条有效 T+1 样本**，按「连板档 × 换手档」分层（模型就是查这张表，不做任何外推）：

| 连板档 \ 换手 | < 12% | 12% ~ 20% | ≥ 20% | 合计 |
| --- | --- | --- | --- | --- |
| 首板 | **18.2%** (577) | 13.0% (139) | 15.1% (53) | 17.0% (769) |
| 2 连板 | **43.3%** (90) | 32.1% (28) | 16.7% (12) | 38.5% (130) |
| 3 连板 | **54.2%** (24) | 30.8% (13) | 33.3% (9) | 43.5% (46) |
| 4 连板及以上 | 50.0% (20) | 14.3% (7) | 25.0% (4) | 38.7% (31) |

（全样本基准再涨停率 **21.8%**，n=976；括号内为样本量）

**置顶纪律：只认「连板概率」，不认「连板数量」。** 上表里 2 连板 & 换手 ≥ 20% 的再涨停率仅
**16.7%**，比首板的 18.2% 还低——如果按连板数置顶，等于把最差的那一类 2 板推到最前面。
所以置顶门槛是**连板概率 ≥ 30%**（`STREAK_TOP_MIN`），连板高度只是查表的输入之一。

**连板是短打，不是持有。** 同批样本 T+3 中位数：首板 −1.03% / 2 板 −1.83% / 3 板 −3.10% /
4 板+ −4.00%——**板越高，三天后越差**。这条写进了置顶标的详情抽屉的醒目警告段。

| 环节 | 做法 | 为什么不偷懒 |
| --- | --- | --- |
| 概率来源 | `limitUpProb(c)` 查上表；换手缺失时取该连板档的**合计值**（不借相邻档） | 借相邻档等于编数据；合计值有真实样本量支撑 |
| 分档文案 | `≥45% 较高 / 30%~45% 中等 / 22%~30% 偏低 / <22% 不佳`（`STREAK_BANDS`） | 档位文案与实测口径同一出处，UI 不重写 |
| 置顶排序 | 三级：达标票（按连板概率降序）→ 其余（按上涨概率降序）→ 净买/代码 | 前提是**两组都按各自的概率排序**，不是把达标票随手扔前面 |
| 标签 | 置顶行打 `大概率连板 54.2%` 徽章（实心红底白字，与上涨概率徽章的淡底区分开）+ 左红边 + 连板样本量 | 视觉上必须一眼能分「这两个数是两回事」，同色系淡底会让人以为是同一个指标 |
| 详情 | 置顶票抽屉首段为「连板预测：T+1 大概率再涨停（已置顶）」，写清分组、样本量、T+3 风险 | 用户点进去第一眼就该知道为什么它被置顶，以及置顶≠拿得住 |

守护方式：`test/picks.test.mjs` 34 例 + `test/predict.test.mjs` 84 例（概率档位边界/六条剔除规则
各自边界/因子单调性/封顶/样本木桶/预期收益两口径/止损同源/**连板分层表逐格对齐实测数字**/
置顶门槛边界与非法回落/置顶只认概率不认板数/未涨停与连板数缺失不给概率/负向注入守卫——其中
「把 `finite` 判据退回 `Number.isFinite(+v)`」的守卫曾抓到 `{turnoverPct: null}` 被当成低换手
白拿加分的真 bug，连板表取档同样复用该判据，否则会白拿高连板概率）；
`check_frontend` 259 项含 30 例推荐相关（概率徽章分档色/连板徽章分档色/连板票全部前置/
置顶行视觉标识/元信息报连板只数/标签 title 写明基准/依据与样本量/止损位/详情五段/
剔除清单折叠面板逐条带实测原因/不构成投资建议声明）。

## 交易预警（src/alerts.js）

一句话：**把「已经算好的档位与账户事实」对照一遍，翻译成用户当场能执行的动作**——
加仓 / 减仓 / 空仓 / 清仓 / 买入 / 卖出 / 持有 / 等待 / 观望。它不产生新的市场判断，
只做「事实 → 动作」的映射；规则只有一个出处（`src/alerts.js`），UI 只渲染不重写。

**双层结构**（每条预警都能追溯到具体字段，杜绝「注意风险」这类空话）：

| 层 | 触发条件 | 动作 | 阈值出处 |
| --- | --- | --- | --- |
| 大盘层 | 情绪分 → 档位 → 目标总仓位，与实际持仓占比偏离超出容忍带 10% | 加仓（机会）/ 减仓（风险）/ 空仓（风险，情绪分 ≤ 24 且有持仓）/ 清仓超额（过热档 ≥ 80） | `picks.marketTier`（与研判报告/回测/推荐同源） |
| 持仓层·止损 | 浮亏 ≤ −8%（止损线） | 卖出全部**可卖**股数（风险级，红） | `config.backtest.stopLoss` |
| 持仓层·接近止损 | 浮亏 ≤ 止损线的 60%（即 −4.8%） | 提示盯住（不与止损并列刷屏） | 同上 × 0.6 |
| 持仓层·集中度 | 单票市值 / 总资产 > 20% | 减仓至上限（给出具体股数，受可卖数量封顶） | 与 `picks.suggestWeight` 的 perStockCap 一致 |
| 持仓层·T+1 | 持仓 qty > 可卖 avail（当日买入） | 等待解冻（说明何时能卖，避免下单被拒） | `paper.settleDay` 的 T+1 语义 |
| 持仓层·到目标 | 档位允许新建 且 单票占比 ≥ 16%（上限的 80%） | 持有、不再加 | 同集中度口径 |
| 持仓层·推荐池 | 今日有推荐池 且 该股不在其中 | 仅提示「无新证据」，**明说不构成卖出依据** | `picks.recommendPicks` |
| 持仓层·停牌 | pxStale 或无当日价 | 说明市值按最近价/成本估算、可能失真 | `paper.accountStats` 口径 |

**三条硬纪律**：
1. **每条例警必须能追溯到具体字段**——抽屉里固定三段：建议动作 / 触发依据（含公式代入过程）/ 当时的字段取值。
2. **只提示，不代下单**：「填入卖出」只把代码与建议数量填进下单区（与研判推荐的「填入下单」同纪律），
   可卖为 0 时数量给 0 并明说 T+1 原因，绝不给出一张必被拒的单。
3. **档位未知时只给风险类预警**：情绪分缺失时不猜档位，大盘层只说明「为什么不建议」（能力边界声明）。

**排序与降噪**：风险 > 机会 > 提示，同级按权重降序；止损已击穿时不再并列「集中度减仓」
（全部卖出已覆盖减至 20%，两条并列会让人以为要做两个动作）；仓位与档位差距在容忍带内不打扰。

**踩过的坑（都有回归测试）**：① `Number.isFinite(+null)` 为 true——「价格缺失」被读成 0 元 →
浮亏 −100% → 凭空触发止损（`+''===0` 同理，与 `picks.marketTier` 踩过的是同一个坑，`finite` helper
显式拦掉 null/空串/布尔）；② 止损股数写成 `freeSell || qty`，可卖为 0 时回退成全部持仓，
预警给出一张 T+1 必拒的单；③ `+null` 陷阱同样会打穿情绪分判档；④ 文案单位重复
（`pp()` 已带 `%` 模板里再补一个 → 「100%%」）——单位只在格式化函数里出现一次，测试锁死。

守护方式：`test/alerts.test.mjs` 31 例（档位边界取等号/大盘层四动作/止损与接近线边界/
集中度整手与可卖封顶/T+1/推荐池不构成卖出依据/停牌不误报止损/严重度排序/每条有 why 与 quote/
空账户/截断/确定性/畸形输入不抛错/**阈值与上游同源**）；`check_frontend` 预警专项 12 项
（卡片三件套/止损点亮/risk 色条/不可卖时填入数量为 0/严重度排序/**填入不自动下单**/
抽屉三段/脚注阈值出处与免责声明/样式三档色条与窄屏折行）；真浏览器（Edge headless 桌面 1440 +
移动 390）以**真实实时行情**核对（浮亏按腾讯实时价计算、止损/集中度/大盘层三风险同屏、
色条 getComputedStyle 断言、零 JS 异常）。

### 预警战绩（收益归因 · src/alert_log.js）

预警的价值不在「说了什么」，而在「说了之后价格怎么走」。归因引擎把每条预警触发时的
**真实价格冻结进台账**（localStorage `paper-alerts-log`，与账户相互独立——重置账户不清战绩），
用之后的真实行情结算，回答用户最关心的问题：**这套预警到底帮我少亏了多少、多赚了多少、准不准**。

- **计分口径**：`照做 vs 不动` 的差额 = 股数 × 价差（不含费用——费用两边都发生，做差抵消）。
  卖出类跌了 = **已规避亏损**（正贡献）；卖出后反弹 = **错杀**、加仓后下跌 = **错过**（负贡献）。
  符号约定唯一：`saved > 0` 恒表示「照做比不做好」。
- **计分股数 ≠ 下单股数**：止损预警常发生在 T+1 全锁时（qty=0 卖不掉），但风险是实打实的。
  台账记 `scoreQty`（全部持仓）用于计分、`qty`（可卖数）用于下单——否则最该被追责的
  止损规则会在台账里消失。
- **无价不算**：取不到当日真实价的条目保持「待验证」，绝不退化成 0 假装算过
  （「没数据」与「没赚没亏」必须可区分）；大盘层没有单一标的价格，只记「应调整多少金额」，
  **不编造收益数字**。
- **幂等落账**：同一天 + 同一层 + 同票 + 同规则只记首次（触发时的价格基准最值钱，
  越晚记越变成「追认」，归因会系统性偏乐观）；界面反复刷新不会膨胀台账。
- **命中率分母只含已有结论的条目**：`|涨跌| ≤ 0.5%` 算「平」、无价算「待验证」，
  都不进分母——命中率 50%（1 对 1 错）与「还没有结论」是两回事。
- **界面**：预警卡片顶部「预警战绩」条（已规避亏损/错杀错过/净贡献/命中率四格，
  规避亏损用蓝色——它既不是涨也不是跌，套红色会像赚钱、套绿色会像亏损），
  点格子开抽屉：按规则拆解表 + 逐条明细（触发价 → 今日价 → 差额）+ 计分口径；
  每条预警抽屉里也带「这条规则的历史战绩」（按 type 聚合——单条预警当天未结算，
  有意义的是这条规则历史上准不准，那才是「要不要照做」的依据）。
- 测试：`test/alert_log.test.mjs` 33 例（幂等/换日换票换规则/无价无量不落账/
  T+1 全锁仍记账且按全部持仓计分/**止损后下跌与反弹两方向**/命中带取等号/
  加仓两方向/无价返回 null 不退化成 0/方向映射覆盖 ACTION 全集/大盘层不编金额/
  汇总对账 ΣbyType.net === net/命中率分母/容量淘汰优先丢已结算/文案金额可核验/
  **minQty 与 paper.LOT 同源**）；负向注入验证：①「无价按 0 算」→ 4 例拦截；
  ②「卖出类符号反转」→ 9 例拦截——两例证明守卫有意义，均已还原。
- 真浏览器（Edge headless 双视口）用**回溯台账 + 实时行情**核对过完整链路：
  000001 记账价 20 元 → 实时 11.57 元，10,000 股止损预警计 **+84,300 元**规避亏损；
  600519 记账价 1000 元 → 实时 1258.62 元，100 股减仓预警计 −25,862 元错杀；
  加仓预警计 −84,300 元错过——四项汇总数字与独立手算完全一致，零 JS 异常。

## 席位身份（买卖双侧明细 + 可核验的席位信息）

龙虎榜本来就披露「买卖各前 5 席位」，但早期版本只落盘了买方明细——用户点开个股只能看到
"谁在买"，看不到"谁在卖"，而**砸盘方往往才是判断接力能不能走的关键**。本轮补齐：

- **采集层**（`src/sources.js` fetchSeats）：`summary.seats.detail` 升级为 v2 双侧结构
  `{ code: { b: [[席位名,万元]...], s: [...] } }`。旧结构（`{ code: [[...]] }` 仅买方）**前端两种都能读**
  （`src/seats.js` seatsOf 统一归一）——存量存档不会因字段升级而重算，历史天数保持 v1 形态；
  管道刷新时检测到旧格式会自动补抓卖方明细（取优合并）。
- **口径层**（`src/seats.js`，ESM 纯函数、Node 与浏览器共用）：席位名解析的唯一出处。
  券商主体（归一「股份有限公司/有限责任公司/(中国)」等写法差异，长词优先防"资管"截断）、
  席位类型六分类（机构专用/沪深股通/券商总部自营/分公司/营业部/其他）、外资券商标注
  （高盛/瑞银/摩根等，多为 QFII 通道性质）、城市（**封闭白名单最长匹配**——第一版用开放式
  正则切分，实测把「南京胜利路」切成「南京胜利」、「上海浦东新区」切成「海浦东新」，
  这种"看起来对细看全错"的结果比返回空更危险，已改为匹配不到就返回空、不猜）。
- **界面层**（个股抽屉）：买方红/卖方绿**两列并排**（窄屏自动堆叠），每行带序号徽章、金额、
  占比与条形；**点任一行**下钻到席位身份页——身份字段、口径解释（该类型席位能说明什么、
  不能说明什么）、同日该席位的其他上榜股（继续点可回到个股）。
- **诚实边界**：市面上流传的"某营业部 = 某游资大佬"名单多数无法核验，且席位会被转租、

### 新鲜度口径（`meta.freshness`）——「滞后」不是一个粘滞的布尔标记

旧口径把 `meta.stale` 当作「上一次尝试是否失败」的标记：只在回退路径置 `true`，成功路径重建 meta 时才会清掉。
于是只要某次回退之后运行一直走「跳过」（龙虎榜未公布 → `main()` 直接 `return null`、不写存档），
`stale` 就会一直粘着，**页面长期误报「数据滞后」，而数据其实已是最新收盘会话**。

现在由 `src/freshness.js` 按交易日历算出三态（成功 / 回退 / 跳过三条路径统一口径）：

| 状态 | 含义 | 页面表现 |
|---|---|---|
| `fresh` | 存档交易日 ≥ 最近一个已收盘交易日 | 无告警 |
| `pending` | 落后 1 个交易日，但预期更新时刻（次交易日 19:30）未到 | 无告警（正常等待 18:30 首抓 / 21:00 补抓） |
| `behind` | 已过预期更新时刻仍然落后 | ⚠ 滞后告警，带落后交易日数与最近已收盘交易日 |

- 「抓取动作的结果」与「数据是否滞后」已解耦：失败/跳过记在 `meta.lastAttempt`（`outcome`/`reason`）。
  即使这次抓取失败，只要数据仍是最新收盘会话就**不会**误报滞后；反之判为 `behind` 一定是真滞后。
- `meta.stale` 保留为派生字段（`= state === 'behind'`）以兼容旧读法；`meta.staleReason` 是人读原因。
- 前端另做一次**纯时间比较**：`meta.freshness.publishDeadline` 是绝对时间戳（带 `+08:00` 偏移），
  客户端本地时钟一过该时刻就提示「尚未更新至最新交易日」。这样页面无需内置交易日历，也不受时区影响。
- 自查：`npm run freshness`（只读；`--write` 落盘刷新判定字段，`--require-fresh` 滞后则退出码 1）。

### 行业离群告警的跨源核验与销案

`src/dirty.js` 的 `OUTLIER_INDUSTRY` 是 **warn**：某行业涨跌幅与「最近的其他行业」相距超过 4pp
且自身 |涨跌| > 8% → 判为「数值孤立，需人工复核是否主题集中」。**为什么不直接判脏**：A 股指数是
自由流通市值加权，小板块暴涨而指数不动恰恰是「轮动」的定义——把真行情判脏等于**把信号当噪声**
（详见该文件内的规则演进注释）。代价是真实行情的离群会**反复报**，久了会被忽略。

销案机制（两层）：

1. **台账** `data/industry_outlier_review.json`——记录已核验的 `(日期, 行业)`：`confirmed-real`
   （真实行情，销案）/ `data-error`（采集异常，继续报警）。**销案条目必须带证据**（复核方式 +
   复算值 + 来源），无证据不得销案（否则销案就成了「不想看的告警就关掉」的后门）。
2. **自动核验** `node scripts/verify_industry_outliers.mjs`——扫全档未销案的离群告警，逐条去
   **同花顺行业指数（881xxx）**拉该日历史日K独立复算：与档案值差 ≤0.05pp → 自动销案并写入台账；
   超容差 → 标 `data-error`、**不销案**、exit 1 报警。拉不到数据同样 exit 1（缺失禁当真值）。
   CI（`daily.yml`）每天跑一次（`continue-on-error`，不阻断数据管线）。

销案只停「重复告警」，**不动任何数值、不改 dirty/干净判定**；命中销案的离群会转为
`suppressedReviews`（可审计：不是"没发现"，是"已核验"）。`--refresh` 才会重写已存在条目
（人工写的证据链优先于机器）。

⚠ **台账不进档案**（2026-10-04 合流定稿）：`src/pipeline.js` **不得**把台账注入 `validateDay`
去写 `emotion.dirty`。台账是可变的**人工复核记录**，一旦参与档案判定，「存档可重现」就依赖它，
且命中销案的天 dirty 留痕会被整条抹掉（销案从"可审计"退化为"静默消失"），幂等守卫
（`test/pipeline_scope.test.mjs`、审计「逐日 status 存档与现算一致」）也会因"存档口径 ≠ 现算口径"
而恒红。**档案只存原始判定**；销案的落点是 `day.review`（`scripts/review_alerts.mjs --apply`
写入，前端经 `signals-latest.json` 的 `dirty.recent[].reviewVerdict` 展示），台账本身则服务于
`scripts/verify_industry_outliers.mjs` 的待核验队列去重。

### 告警排查顺序

1. `npm run freshness` —— 先看**判定**，而不是只看 `meta.stale` 字段（该字段可能是旧口径写入的）

4. 怀疑某源不可达：`node scripts/probe_sources.mjs` —— 逐源打印 HTTP 状态与关键字段，

### 三条硬规矩（都是被真实故障教出来的）

- **降级 ≠ 成功**：`fallbackArchive` 是容错设计（不崩页、不误导），本身不会让 job 失败。
  故 workflow 末尾加了**新鲜度门禁** `node scripts/freshness.mjs --require-fresh`：真滞后则本次运行标红
  （GitHub 会发失败通知）。`pending` 不误伤——18:30 因龙虎榜未公布而跳过不会判红，21:00 补抓仍不成才会红。
  另外「跳过」路径现在也会打 `::warning::` 注解，Actions 里不再静默。
- **push 必须比对 SHA**：`git rev-parse HEAD` 与 `git ls-remote origin main` 必须一致，曾经出现「以为推上去了其实没有」。
- **本机直跑要防静默**：`if (import.meta.url === 'file://' + argv[1])` 在 Windows 上恒不成立（`argv[1]` 是 `C:\…`），
  会让 `node src/pipeline.js` 一行不输出地"成功退出"。已改用 `pathToFileURL(argv[1]).href` 比较。
- 教训（2026-09-29「数据滞后」告警）：第一层根因不是网络故障，而是 `pipeline.js` 里一个**未定义变量**
  （`old` 应为 `history[i]`）使 `runLive` 每次重跑当日数据都抛 `ReferenceError` → 整体回退 → `stale` 恒为 `true`、
  数据永不更新，而 job 始终显示成功。第二层根因是 `stale` 本身是**粘滞标记**（见上），故在修 bug 之外重做了新鲜度口径。
  回归测试：`test/merge.test.mjs`（合并语义）、`test/freshness.test.mjs`（三态判定与节假日）。

## 分支与合并节奏（staging → main）

**`main` 是对外可用分支，`staging` 是唯一开发分支。** 所有改动先进 `staging`，攒够了再整批进 `main`。

### 合并的唯一合法入口

`.github/workflows/merge-staging-to-main.yml`。**不经这条工作流的 `staging → main` 合并一律视为违规操作。**

为什么必须机器化而不是"想起来手动 `git merge` 一下"：本系统的产出（情绪分、分位、归档、前端断言）全部建立在**口径一致**上。`main` 上一旦出现"口径漂移但没人发现"的状态，故障特征是**静默**的——页面照常渲染、数字看着也正常，只是和 `staging` 对不上。事后归因代价极高（参见 2026-10-01 外围事故）。

### 三条规则

| 规则 | 内容 |
|---|---|
| **① 定期** | 每周一 09:30（北京）自动尝试合并，把上一周的 `staging` 成果整批带进 `main`。选周一开盘前：周末数据静止，`staging` 处于"上周产物已落库、本周尚未开盘"的稳定态，合并风险最低。 |
| **② 门槛（硬）** | **五道门禁全绿才允许合。** 任何一道红 → 本次不合并，`main` 保持原状，只留记录（不阻断后续）。 |
| **③ 加塞例外** | 重大 bug 修完可**不等周一**，用 `workflow_dispatch` 手动触发。⚠ **加塞只改时机，不改门槛** —— 门禁全绿这一条永远不放松。触发时请填 `reason`（写明是哪次重大 bug 修复）。 |

**自由 merge 不允许** —— 目的是避免"绕过门禁"被当成常规手段滥用。

### 五道门禁（合并前逐条跑，与 `daily.yml` 同源）

| # | 命令 | 守什么 |
|---|---|---|
| ① | `node --test test/*.test.mjs` | 单元测试：Python↔JS 夹具、口径锁、幂等锁、决策锁、**前后端接口契约锚定**（当前 1264 条） |
| ② | `node scripts/audit_lhb_caliber.mjs` | 龙虎榜双口径不混用 + 存档可重现 + `run` 行先后 + 体积纪律 |
| ③ | `node scripts/check_frontend.mjs --require-jsdom` | 前端断言：jsdom 里真跑 `index.html` + `app.js` |
| ④ | `node scripts/version_regression.mjs` | 公式版本回归：v4.5 / v5.0 / v5.2 并行重算对比 |

### 前后端接口契约（V5.3 同步机制）

后端（Node 管线）与前端的全部接口是 `data/*.json` 数据档——没有 API 层，**数据档即接口**。历史上字段名曾两侧各自演化（`missingNote`→`missingReason`，commit 57a12b7：前端显示"原因未知"，后端文案丢失），根因是没有单一事实源。现以 `schemas/*.json` 契约锁定：

| 契约 | 数据档 | 生产方 | 消费方 |
|---|---|---|---|
| `schemas/signals-latest.schema.json` | `data/signals-latest.json` | `src/archive_split.js` `buildSignals` | `app.js` 各面板 + `src/dataset.js` |
| `schemas/backtest.schema.json` | `data/backtest.json` | `scripts/backtest.mjs` | `app.js` `renderBacktest`（V5.3 对照段/净值曲线） |
| `schemas/version-regression.schema.json` | `data/version-regression.json` | `scripts/version_regression.mjs` | `app.js` `renderVerCmp`（`satThreshold` 全站唯一出处） |
| `schemas/archive-index.schema.json` | `data/archive-index.json` | `src/archive_split.js` `buildIndex` | `app.js` 首屏（`REQUIRED_ON_BOOT` 唯一成员） |
| `schemas/global.schema.json` | `data/global.json` | `scripts/fetch_global.mjs` | `app.js` `renderGlobal`（外围三相位） |
| `schemas/intraday.schema.json` | `data/intraday.json` | `scripts/snapshot_intraday.mjs` | `app.js` `loadIntraday`（仅 live 相位） |

**契约语义两条**：① `required` = 前端渲染**实际消费**的字段（消费面，非生产面自画像——否则后端漏产、契约跟着漏，锁等于没锁）；② 整段 `anyOf null`（未生成 ≠ 没有，前端有专门缺失分支），但**段一旦存在，段内 required 必须齐**——半缺是最危险形态（渲染静默空白）。

**变更流程（顺序不可反）**：

1. 先改 `schemas/*.json` 契约（字段/类型/枚举），提交信息注明「契约变更」——diff 即对相关方的通知；
2. 同步改另一端代码：产出方（`src/archive_split.js` / `scripts/*.mjs`）或消费方（`app.js`）；
3. 跑 `node scripts/check_contract.mjs`——门禁红到两端对齐为止；
4. 若字段语义变化（不只增删），在 `check_frontend.mjs` 补对应渲染断言（效果级锁）。

自动化拦截：`daily.yml` 在数据档落盘后、提交与 UI 构建前跑 `check_contract.mjs`（坏档不进提交）；`node --test` 含 `test/contract.test.mjs`（磁盘档锚定 + 校验器语义 + 事故重演负向演练），周合并门禁①自动带上。错误输出带 JSON Pointer 路径 + 期望/实际 + 修复顺序指引。跨语言面（Python `tools/backtest/`）由 parity 夹具 + 七因子 schema 测试另行锁定，不在本契约重复。

### 两处刻意的硬约束

- **门禁③ 必须带 `--require-jsdom`。** jsdom 不是仓库依赖（`node_modules/` 已 gitignore），而 `check_frontend.mjs` 在缺依赖时**默认跳过并返回 0**——在开发机上体贴，在 CI 里就是**假绿**：门禁显示"通过"，实际一条断言都没跑。正是"没检查 ≠ 没问题"的反面教材。故工作流显式传 `--require-jsdom`，缺依赖直接失败（退出码 1），并在 runner 临时目录装 jsdom、用 `NODE_PATH` 指过去，不给仓库增负担。
- **只允许 fast-forward（`--ff-only`）。** `main` 上不该有 `staging` 没有的提交。若 ff 失败（历史已分叉），说明有人绕过本工作流直接推过 `main`——这种情况**必须人工裁决**（把 `main` 的独有提交合回 `staging`，或明确废弃后重跑），**绝不**自动化地产生一个 merge commit 把分叉糊过去。

### 防"验的"与"合的"不是同一个 commit

门禁 job 与合并 job 分列，门禁跑完把被验的 `staging` SHA 经 `outputs` 传给合并 job；合并前**再核对一次**。若两次不一致（说明验完之后 `staging` 又动了）→ **拒绝合并**。不能拿"验过的绿"去背书"没验过的 commit"。

### 门禁红时的行为

门禁未全绿 → 独立的 `blocked` job 把结论写进 Actions Summary（"本次未合并、`main` 未改动、下一步怎么修"），并退出码 1。**不**让 Actions 里只剩一片 `skipped` —— 那样事后完全无从归因。



- **零 bug 不存在**：凡拉第三方行情（东财/同花顺/腾讯）的系统，源方限流、改格式、封 IP 都无法在代码层根除。本系统的优势是**失败可降级**（不崩页、不误导）。
- **live 抓取需云端验证一次**：`src/sources.js` 在本地沙箱禁网，逻辑靠 unit test + 离线回放保证；真实字段解析要在 Actions 跑通一次（日志可见）。解析失败时 pipeline 走回退档、本次抓取记入 `meta.lastAttempt`（不展示错误数据）；**只有因此落后于最近已收盘交易日且已过预期更新时刻**才显示滞后告警，并由 workflow 末尾的新鲜度门禁让该次运行标红（详见「数据更新与故障排查」）。
- 历史分位基于存档长度（默认窗口），样本越长越准；建议长期运行积累。
- **外围模块的两处能力缺口**（已知，非 bug）：① 新浪不提供**美债收益率**（`gb_$tnx` 返回空），
  长端利率这个分母端锚点只能通过美元指数/黄金间接观察；② 外围只做**方向性观测**，不做量化传导——
  「费半跌 2% 对应 A 股元件板块跌多少」这类映射本系统不给，因为没有可验证的传导系数。
- **模拟器刻意保留的简化**（都在 `src/paper.js` 文件头注明依据；台面已下线但引擎保留，记录仍然成立）：
  ① 撮合价用**收盘价**而非分钟级
  撮合（存档是日频的，没有盘中价可用）；② 不模拟**分红送股/配股/退市**对公司行为的影响，持仓跨
